# 猫つぶし Webアプリ実装仕様書

版：1.0 ／ 作成日：2026-10-23 ／ 対象：企画・デザイン・素材制作・フロントエンド開発・品質確認

本書は、提示済みの6枚を基準に、6つの暇つぶしモードをメニューから選べるWebアプリを実装するための仕様書である。今回の成果物は仕様・原画像・実装用の参照情報であり、アプリ、分離済み素材、アニメーションはこれから制作する。

## 01 企画の決定事項と完成条件

### 1.1 作るもの

ゲーム名は **「猫つぶし」**。スマートフォンの縦画面で、指1本で猫にちょっかいを出し、表情や仕草を楽しむ。ひとつのWebアプリに6モードを収録し、初回からすべて選べる。PCではマウスで同じ操作ができる。

ユーザーが指定した重要条件は、①気楽な暇つぶし、②6モードをメニューで選択、③提示画像の見た目の忠実な再現、④猫のキャラクター品質、⑤画像を逐一見ながら制作・照合すること、⑥まずWebアプリとして作ること、である。

| 区分 | 本書での扱い |
| --- | --- |
| 固定する要件 | ゲーム名、6モード、指1本、短時間、元画像のアート、メニューからの選択 |
| 初版の設計判断 | 縦画面優先、2D/2.5D合成、端末内の記録保存、アカウント不要 |
| 調整できる数値 | 制限時間、予告時間、追跡速度、押せる領域、演出時間、配信容量 |
| 追加設計する画面 | メニュー、読み込み、一時停止、結果、設定、エラー表示 |
| 追加制作する絵 | 通常顔、開眼、ジャンプ途中、パンチ、帽子なしの頭、頬の戻りなど |

初版は6モードの遊びと猫の品質に集中する。オンライン対戦、ランキングサーバー、ログイン、決済、広告SDK、ガチャ、育成、デイリーミッション、ネイティブアプリ化は初版の納品範囲に含めない。公開先・独自ドメインは実装時に決める。

### 1.2 「完全再現」の実務上の定義

6枚の原画像を、静止画の構図・猫の顔・被毛・色・小物・文字装飾の正本とする。実装者の好みで別の猫や別の画風に変更しない。仕様の文章と画像の見た目が衝突する場合、見た目は原画像を優先し、操作や判定は本書を優先する。

目標は、指定した基準状態を実際のゲーム画面で呼び出したときに、元画像と同じ印象・構図・細部になること。原本の画素をそのまま使う部分は同じ画素を保持する。切り抜き、隠れた部分の補完、動的な文字組み、未描画の姿勢には制作と照合が必要であり、単一の静止画像から動画や隠れ面が一意に得られるとは扱わない。

6枚は同じ系統の猫だが、カメラ、顔の誇張、目や足の比率が異なる。共通のキャラクター設定を持ちつつ、各モードの絵を個別に再現する。1枚の猫を拡大縮小して全モードへ流用することを完成としない。

完成判定は **見た目・動作・遊び・Web上の安定性** の4つをすべて満たすこと。元スクリーンショットを画面全体へ貼っただけの状態は照合用資料として扱い、実装完了にはしない。

### 1.3 初期の遊び方

| ID | モード | 操作 | 初期の1プレイ | 記録 |
| --- | --- | --- | --- | --- |
| 01 | ねこつんつん | 閉眼中だけタップ | 30秒、見つかると短く反応して続行 | 成功タップ数 |
| 02 | 箱をずらせ | 入る直前に横へドラッグ | 30秒 | 成功回数 |
| 03 | 猫パンチ寸止め | 長押しし、パンチ前に離す | 数秒の1試行 | 成功時の長押し秒数 |
| 04 | その帽子、いやニャ！ | 帽子が外れたらタップ | 15秒 | 装着回数 |
| 05 | ほっぺむにむに | 頬をドラッグして離す | 無制限 | 得点・失敗なし |

これは初期チューニング値であり、遊んだ結果によって調整する。画像内の「12回」「あと18秒」等は、実装照合に使う途中状態であり、開始時の値ではない。

## 02 メニューと画面遷移

### 2.1 メニューの新規デザイン

メニューは今回の6枚には存在しないため、以下を新規仕様とする。既存画面と同じ暖色・クリーム・茶色・丸い文字を使い、猫の絵を最も目立たせる。

- 上部にゲーム名「猫つぶし」。右上に音設定。装飾は控えめにする。
- 中央は2列×3行のモードカード。並びは左上から01、02、03、04、05、06。
- 各カードは猫のサムネイル、番号、モード名、短い操作説明で構成する。カード全体を押せる。
- 全モードを最初から開放する。「準備中」「Coming soon」で納品しない。
- カード名は原画像の名前を使う。06はカード内で「あとちょっとで／届くのに」の2行にできる。
- 最高記録はカードの小さな補足として表示できる。05は「いつでも・気ままに」とする。

390px幅で左右16px、列間12pxを初期値にする。カードの画像部は約104px、文字部は約56px。小さい端末や文字拡大では自然な縦スクロールを許す。6枚を詰め込むために文字を小さくしない。画面高が十分な場合は6つを一度に見渡せる。

サムネイルは最終的な各モード素材から書き出す。元画像の点数や説明が小さく焼き込まれたままのサムネイルにしない。01はつつかれ顔、02は驚いたジャンプ、03は上げた前足、04はバナナ帽子、05は伸びた頬、06は羽へ手を伸ばす姿を使う。

| 画面 | 主な内容 | 次の操作 |
| --- | --- | --- |
| メニュー | 6カード、音設定 | カードをタップ |
| モード準備 | 猫と1行の説明、最初の操作を待つ | モードごとに定めた開始操作 |
| プレイ中 | 猫、必要な数字、短い説明 | 指1本で操作 |
| 一時停止 | 「つづける」「メニューへ」 | 操作を明示して再開 |
| 結果 | 猫の短い反応、今回・最高記録 | 「もう一回」「メニューへ」 |
| 読み込み失敗 | やさしい文言と再試行 | 「もう一度読み込む」 |

### 2.2 遷移と入力の持ち越し防止

メニュー → 選択モードの素材を読み込み → 準備 → 最初の有効な操作 → プレイ → 結果、を基本とする。05は準備からそのまま自由操作し、結果画面を出さない。03は結果から1タップで次の試行へ進める。

カードを押した指が離れるまで、ゲーム内の最初の入力として扱わない。結果ボタン、設定、戻るのタップが背後のゲームへ伝わることも防ぐ。メニューへ戻ると、前モードのタイマー、アニメーション、音、イベント購読、入力所有権を解除する。

### 2.3 共通操作を元の構図へ重ねない

原画像の外側に44CSSpx以上の共通ナビゲーション領域を置き、「メニューへ」「音」「一時停止」を配置する。これにより元画像内のタイトル、猫の耳、帽子を押し下げない。

06の一時停止は原画像右上のボタンに接続し、外側には重複して置かない。05は原画像右上のリセットを「頬と演出を初期状態に戻す」ボタンにする。05に残り時間やスコアは追加しない。

プレイ中にメニューへ戻る場合、短いゲームなので確認ダイアログを挟まず、そのプレイを終了する。結果表示や一時停止からの再開には追加の長い説明を置かない。

## 03 画面サイズ・UI・文字の再現

### 3.1 基準座標

6枚の原本はすべて **941×1672px**。論理座標もこのサイズで統一する。単純な9:16へ変更して僅かに切り取る処理は行わず、941:1672の比率を使う。

表示倍率は `s = min(利用可能幅 / 941, 利用可能高さ / 1672)`。ステージは `941s × 1672s` とし、余る領域は周囲のクリーム色で埋める。猫や文字を縦横別倍率で伸縮しない。元画像で意図して切れている箱・頬・手の位置はそのまま保つ。

タッチ位置はステージの実DOM矩形から、`x=(clientX-left)×941/rect.width`、`y=(clientY-top)×1672/rect.height` で変換する。DPRは描画バッファ解像度へ使い、当たり判定へ二重に掛けない。

safe-area、ブラウザ上部バー、共通ナビゲーションを引いた領域へステージを収める。縦持ちではプレイ面をスクロールさせない。横持ちやPCでは縦のステージを中央へ置く。横持ち時は必要なら「縦にすると大きく遊べます」をステージ外に表示し、強制的な回転待ちにはしない。

### 3.2 画面ごとの装飾を保つ

| モード | 原画像のUIの違い |
| --- | --- |
| 01 | クリーム色の丸いタイトル・数値プレート、オレンジの数字、薄桃色の説明プレート |
| 02 | 茶色の数値プレート、黄色の数字、白縁の「スカッ！」、黄色い説明下線 |
| 03 | 茶色の太い縁取り文字、肉球付きタイトル、黄色い数字、前景の大きな手 |
| 04 | クリーム色プレート、オレンジの数字、帽子付近の加点・星、下部タップ輪 |
| 05 | プレートなしのタイトルと黄色い下線、灰色のリセット、小さい説明プレート |
| 06 | 茶色のタイトル・時間・説明プレート、右上の一時停止、白青の操作軌跡 |

共通コンポーネントは使ってよいが、6画面のタイトルや時間表示を一つの見た目へ一律変更しない。値、単位、文言はゲーム状態から描画し、古い画像内の数字を残したまま新しい数字を重ねない。

### 3.3 フォントとアイコン

原画像のフォント名は不明。日本語の太い丸ゴシックを候補として、実際の文字幅・縁取り・字間を原画像と照合する。M PLUS Rounded 1c等は候補であり、採用時に配布元・ライセンス・必要なウェイトを確認する。書体名だけで一致と判断しない。

通常の説明文と動的な数字はHTMLのテキストとして保持する。数値には幅の安定した数字組みを使い、桁が変わってもプレートと他のUIが跳ねないようにする。原画像の固有な静的装飾文字を画像で保持する場合は、同じ内容のアクセシブルなラベルを別に持つ。

音・戻る・一時停止・リセットは一貫したアイコンセットまたは専用アセットを使う。猫、帽子、箱、羽、髭を絵文字や単純図形で代替しない。標準ボタンの背景や枠はCSSでよい。

参考色は、濃茶 `#4A2514`、クリーム `#FFF3DA`、オレンジ `#FF941A`、黄色 `#FFD64A`、薄桃 `#FFE1DA`。これは実装開始用の近似トークンであり、最終色は原画像に合わせる。

## 04 描画方式とWebアプリ構成

### 4.1 初版の主案

**高品質なラスター素材＋局所的なメッシュ変形＋必要な動作の短い連番**を採用する。毛並み・陰影・背景ぼけは素材制作時に仕上げ、Web上で合成する。猫が高品質になるかどうかは、描画ライブラリ名ではなく、元絵の扱い、追加素材、時間的な一貫性で決まる。

| 担当 | 推奨する役割 |
| --- | --- |
| TypeScript | ゲーム状態、時間、判定、型、保存データ |
| Vite等のビルド環境 | 開発、配信アセット処理、静的Web配信 |
| React等のDOM UI | メニュー、結果、設定、読み込み、アクセシブルな操作 |
| PixiJS | 背景、猫、小物、Sprite/AnimatedSprite、頬のMesh |
| Web Audio等 | 操作を契機とする短い効果音 |
| Playwright等 | メニュー遷移、入力、基準状態の画面キャプチャ |

PixiJSのSpritesheetは画像とフレーム情報からSpriteやAnimatedSpriteを扱え、Meshは頂点やUVを制御できる。これらを本企画の素材構造に合わせて用いる。[S1][S2]

具体的な依存バージョンは実装開始時に公式ドキュメントで確認し、ロックファイルへ固定する。フレームごとの座標更新をReactの再レンダーへ流さず、ゲームループ側で更新する。

### 4.2 3Dを使う場合の位置づけ

ジャンプ、パンチ、俯瞰ポーズの連番を整えるために、Blender等で猫モデル・リグ・毛・照明を作り、制作時に画像へレンダリングする方法は有効な選択肢とする。Web側にはレンダリング結果を渡す。髪・毛のカーブや制作向けレンダラーは公式の機能資料を確認して選ぶ。[S7][S8]

ブラウザ内で高密度の毛を常時リアルタイム3D描画することは初版の必須条件としない。採用する場合も「同じ猫に見えること」「原本のカメラ」「指定実機での動作」の同じ合格条件を満たす。

### 4.3 モジュールの責務

| モジュール | 責務 |
| --- | --- |
| AppShell / Menu | 画面遷移、共通ボタン、設定、結果 |
| GameHost | モード開始・中断・終了、素材ライフサイクル |
| InputRouter | 1本の入力所有権、座標変換、キャンセル |
| GameClock | active time、停止、再開、テスト用の時刻制御 |
| AssetManager | モード単位の読込、参照数、不要テクスチャ解放 |
| CatActor / PropActor | 猫・小物の姿勢、アニメーション、接触位置 |
| Mode01〜06 | そのモードの状態遷移と判定のみ |
| RecordStore | 設定・最高記録の端末内保存とバージョン管理 |
| VisualFixture | 原画像と同じ実装状態を再現する検証用入口 |

ゲーム時計・乱数・入力は差し替え可能にする。検証用Fixtureは本番と同じSceneとCatActorへ状態を渡し、別の静止画ページを代わりに表示しない。ゲーム開始後の画像生成API呼び出しは不要な構成とする。

## 05 猫の品質を上げる制作仕様

### 5.1 キャラクターの基準

共通の猫は、頭と頬が大きい茶トラ、白い口周りと胸、短いピンクの鼻、白い長い髭、淡いピンクの肉球、密な被毛を持つ。目は琥珀〜茶色を基調に、モード02・06の大きい白目や口の誇張を原本どおり許容する。

制作時は正面・斜め・俯瞰の資料、通常・閉眼・疑い・不満・驚き・得意顔の表情表を作る。これは追加制作物であり、6枚が同じ3Dモデルの各視点であると仮定しない。鼻と目の位置、白毛の形、額の縞、頬の厚さ、耳の比率を、モード別の原本に結び付けて管理する。

### 5.2 素材の作り方

1. 原本PNGを読み取り専用の基準として保存し、SHA-256で識別する。
2. 各原本を開き、猫・背景・小物・手・影・文字・効果を区分する。
3. 猫やUIを除いた背景のクリーンプレートを作る。後から見える床・クッションを補完する。
4. 猫を、必要な可動部だけレイヤー分解する。頭、胴、瞼、耳、前足、尾、頬、髭など。
5. 手や帽子の下に隠れた顔・頭、腕の付け根、頬の外側を描き足す。隠れ面は新規制作として記録する。
6. 毛先と髭を保った透明マスターを作り、白・黒・実背景で縁を確認する。
7. 同じマスターまたは同じリグから、原本にない表情・主要ポーズを作る。
8. 基準状態を一度合成し、原本と重ねてからアニメーションを追加する。
9. 必要な部位をアトラス化し、縮小・圧縮後の見た目を実画面で確認する。

画像生成を素材補完に使う場合は、毎回正本と直近の承認済みマスターを参照し、「変更してよい部分」と「維持する顔・毛・光・カメラ」を明記する。1コマずつ無関係に生成し、それを無検品で動画化しない。

### 5.3 毛並み・立体感の品質条件

- 頬、耳、尾の輪郭に細い毛が残る。切り抜きの硬い縁や白黒のハローを残さない。
- 元の暖色の縁取り光、白毛の陰影、背景ぼけを保つ。白い口周りを真っ白な平面にしない。
- 目には虹彩、瞳孔、反射を残し、視線と眉・瞼を連動させる。
- 髭は根元と先端を区別する。頬を動かしたときに全髭が同じ直線として伸びない。
- 影は猫本体から分離し、跳躍しても床に残す。高さによって大きさ・濃さを変える。
- 帽子のぬいぐるみ感、箱の紙、猫じゃらしの羽の繊維も、猫と同じ質感水準へ揃える。

### 5.4 解像度とアルファ

941px幅の原本は基準品質として保全する。単純な拡大は毛の新しい情報を増やさない。より大きな制作マスターが必要な部分は、高解像度で再制作し、元の顔が変わっていないか確認する。

配信素材の解像度は、最大表示サイズと採用DPRから決める。原本以上へ表示を拡大した際の鮮明さは別検証とする。透明マスターはPNG等、配信用はWebP等を候補にし、毛先・髭の劣化を確認してから採用する。

アトラスの切り詰め後も元のサイズとアンカーを保持する。輪郭には数pxのパディング・色にじみ対策を設け、縮小時に隣の絵が混ざらないようにする。プリマルチプライドアルファの扱いは書き出しと描画で統一する。

### 5.5 動きの設計

呼吸、耳、尾、視線は小さな継続動作として扱う。まばたきは瞼の差分を作り、目の画像を縦に潰すだけにしない。大きなジャンプ・パンチ・頭振り・俯瞰の手伸ばしは主要ポーズと短い連番で形と遠近を維持する。

ゲームの描画更新は60fpsを目標にするが、絵の差分枚数とは別である。動作連番は24fps相当を最初の候補とし、止め・予備動作・主動作・余韻を含めて確認する。二重像が見えるクロスフェードを使って枚数不足を隠さない。

| 動き | 初期の演出目安 | 見るポイント |
| --- | --- | --- |
| タップの反応 | 80〜160msで押し込み、180〜320msで戻る | 接触位置が一致する |
| まばたき | 閉じる・開くを含め100〜220ms | 瞼と毛の境界が自然 |
| 予告 | モードごとに明示した時間以上 | 表示より先に判定しない |
| 頬の復元 | 約450msで収束 | 鼻や目が伸びず、過剰に振動しない |
| 成功・失敗の余韻 | 300〜700ms | 次の入力を不必要に待たせない |

音は短い柔らかな「ぷに」「ぽふ」「すかっ」等を使い、表情を補強する。悲鳴や痛みの写実的な表現は入れず、原画像の漫画的な不満・驚きのトーンを保つ。

### 5.6 モード05の局所変形

元画像はすでに右頬が伸びているため、最初に非変形の顔を制作する。左右の頬の影響範囲、目・鼻・耳の固定点、外周の余白、髭の追従点を持たせる。

初期実験では頬周辺に12×12〜20×20程度の頂点格子を置き、つまんだ点から離れるほど変形が減るようにする。頂点数は品質・負荷を確認して決める値であり、これだけで自然な顔になるわけではない。[S2]

水平の引っぱり上限はステージ幅の約16%から調整し、縦は高さの約6%に制限する。上限を超えた入力には柔らかい抵抗をつける。鼻・反対の目・頭蓋は固定し、三角形の反転・隙間・毛の極端な引き延ばしを防ぐ。原本と同じ伸び状態を再現するための例外的な静止オーバーライドではなく、通常の変形パラメータから到達できるようにする。

戻りは減衰する弾性運動とする。頬の動きに髭の根元が追従し、先端に短い遅れが出る。小さい手の絵は2本の指でつまんでいても、ユーザーに必要な入力は1本指のドラッグだけとする。

### 5.7 先に試す品質の関門

まず01の「通常・つつかれ・開眼」と05の「通常・最大変形・戻り」を、高品質素材で短く実装する。この2点で、毛並み・顔の同一性・切り抜き・応答・変形方式を確かめる。問題が残る場合は素材やリグを直してから、残るモードへ広げる。

### 7.2 必要な素材と動作

背景のクリーンプレート → クッション → 猫の胴体・足 → 尻尾 → 頭・頬 → 瞼/開眼差分 → 髭 → 指 → 接触効果 → UI、の重なりを基本にする。前足の足先は白くふっくらしている。頭全体を一枚のまま上下に揺らすだけにせず、呼吸・耳・尻尾・瞼の小さな独立した反応を用意する。

指は原本中の演出用カーソルであり、端末の実際の指とは別。画面を操作するたび同じ指が不自然に複数現れないよう1本に制限する。指の接触位置と頬の沈み込み、リングの中心を一致させる。

原本から分かるのは閉眼中・12回・残り18秒の接触フレーム。開眼姿、見つかった反応、回復、通常時の指の退避、頬の戻りは追加制作が必要。

### 7.3 静止照合の要点

クッションの厚み、頭の大きさ、閉じた瞼の角度、指が頬を押す位置、足と接地影を優先。開いた目を原本の閉眼状態に混ぜない。数字や効果は画像に焼き込まず、照合用状態で「12」「18」「+1」を再現する。

### 7.4 遊びの流れ

1. 猫が目を閉じる。猫の操作領域をタップすると1回加点し、ほっぺが少し動く。
2. 猫の耳・眉が動く予告が500ms入る。この間は目が閉じており、まだ正しくつつける。
3. 猫が目を開ける。プレイヤーはタップを止める。
4. しばらくするとまた目を閉じる。30秒の間これを繰り返す。

### 7.5 状態と初期値

| 状態 | 長さ | タップの扱い | 次の状態 |
|---|---:|---|---|
| `CLOSED` | 1.4〜2.2秒 | 有効タップ1回につき+1 | `WARNING` |
| `WARNING` | 500ms固定 | +1。耳・眉だけが予告し、目は閉じたまま | `OPEN_GRACE` |
| `OPEN_GRACE` | 120ms固定 | 加点もミスもなし | `OPEN` |
| `OPEN` | 880〜1,280ms | 新しい押下、または押したままの接触で発見される。加点なし | 通常は`CLOSED`、発見時は`CAUGHT` |
| `CAUGHT` | 1.5秒固定 | 全入力を採点せず、猫がこちらをにらむ | 新しい`CLOSED` |

- 通常の開眼時間は猶予を含めて1.0〜1.4秒。
- 各閉眼時間・開眼時間は、その周期に入る時に一度だけ決める。タップの速さを見て直前に開眼を早めない。
- 予告500msと開眼後120msの無判定区間で、視覚反応と入力の境目に余裕を持たせる。
- 発見時も総残り時間は減る。成功回数そのものは減らさないため、画面の「回」の意味が途中で変わらない。
- 目を開けたまま連打すると1.5秒の操作不能になる。これは通常の開眼の残時間より長く、止まらず連打し続ける方が有利にはならない。
- `CAUGHT` 終了後は必ず通常の閉眼から再開し、新しい予告500msを省略しない。

### 7.6 判定上の注意

- 長押し1回を連打として扱わない。1回の押下・離しにつき最大1点。
- 加点候補が300msを超えたら、その候補は無効にする。ただし、指が押されたままという接触状態は保持する。移動量が12 CSS pxを超えて加点候補でなくなっても同様。
- `OPEN`へ入った瞬間にまだ操作中の指が残っていれば、その時点で1回だけ発見判定を行う。`OPEN`中の新しい押下も、離すまで待たずその場で発見とする。長押しのまま300msを超えれば発見されなくなる、といった判定抜けを作らない。
- 発見したら未確定の加点候補を破棄し、その押下に対する後続の`pointerup`を加点に使わない。`CAUGHT`中は同じ接触から反撃を重複発生させない。
- 150ms未満の追加押下は加点候補にしない。ただし開眼中の発見判定は省略しない。
- 30秒に達した時点で新しい入力・発見・加点をすべて閉じる。反応中でも結果へ進み、反応演出の終了待ちでプレイ時間を伸ばさない。
- 目の画像が開眼状態へ変わる時刻と、ゲーム上の開眼判定の時刻を同じ状態更新から決定する。
- 中断復帰時は未確定のタップを破棄し、経過秒・得点・目の状態・その状態の残時間を保持する。再開操作の後、400msだけその表情を見せる準備時間を設け、この間は時計も状態も止めて採点しない。その後に続行し、短く残った警告も見落としにくくする。再開によって閉眼時間を新しく獲得したり、点が付いたりはしない。

### 8.2 必要な素材と動作

背景・ラグ → 猫の接地影 → 猫の後脚/胴/尾 → 猫の頭/前脚 → 箱 → 残像・軌跡・効果 → UI。箱の前後関係は猫が箱の中へ入る場合に切り替える必要があり、箱は少なくとも「後ろの面」と「手前の面・縁」の2レイヤーを持つ。ラグの影を猫本体へ焼き込むと跳躍時に影も一緒に浮くので分離する。

### 8.3 静止照合の要点

猫の浮遊位置、白目の大きさ、四つの肉球、箱の大きさ・右端の切れ方、ラグの明るさ、箱の残像の位置。スワイプ軌跡をゲームの常設矢印にせず、操作中/説明時の短いエフェクトにする。

### 8.4 遊びの流れ

1. 猫が中央の箱に近づく。
2. 猫が体を低くする予備動作を見せ、飛び込む。
3. 猫が空中にいる間に箱を左右どちらかへスワイプする。
4. タイミングが合えば猫は元の位置へ着地して不満顔。早すぎると猫が移動先の箱へ入る。着地はいずれも柔らかい床の上で、負傷は描かない。

### 8.5 1回の遭遇の初期値

| 状態 | 長さ | 内容 |
|---|---:|---|
| `APPROACH` | 0.9〜1.5秒 | 猫が箱へ近づく |
| `CROUCH` | 450ms固定 | 飛び込む予備動作 |
| `JUMP` | 600ms固定 | 離陸時の箱の位置へ向かう |
| `REACTION` | 450ms固定 | 箱に入る／箱の横で不満顔。次の遭遇へ |

- 1回約2.4〜3.0秒。30秒で複数回遊べる。7回成功して残り12秒などのキャプチャ状態も成立する。
- 各遭遇の開始時、箱は横位置`0.5W`へ戻る。猫の出現位置・向きも毎回プレイヤーが迷わないように固定する。
- 1回の遭遇で成功するのは最大1回。スワイプを往復させても追加点は出ない。

### 8.6 スワイプの確定条件

- 箱と周辺の広めの操作領域から始めた1本指の横スワイプを受け付ける。
- `abs(dx) ≥ 12 CSS px` かつ `abs(dx) ≥ abs(dy)` になった時を、横スワイプ開始とする。触れただけではスワイプ開始にしない。
- 成功には、次の両方を満たす必要がある。
  1. **横スワイプを始めた時点が離陸後である。**
  2. **離陸から520msまでに、箱の横移動量が`0.22W`に達する。**
- 成功条件を満たした時点で1点を確定し、表示回数を更新して「スカッ！」等の成功演出を短く出す。箱をその方向の`0.25W`移動位置へ固定し、その遭遇の入力を閉じる。猫はまだ空中のまま、その後に着地へ続く。原画像の空中の猫・7回・「スカッ！」を同時に再現できること。
- 箱の操作中心の横移動上限は、初期中心から左右それぞれ`0.28W`を基本とする。箱の絵の右端などが原画像どおり画面外へ切れることは許容する。絵の外接矩形をすべて画面内へ収めるために構図を縮めない。
- 箱の操作中心と有効な44 CSS px以上のタッチ領域は触れる範囲に保持する。視覚上の端切れと操作領域の制限を別に扱い、左右どちらでも成功に必要な`0.22W`の移動量を確保する。
- 離陸前に横スワイプを始めたら、その遭遇は`EARLY`として確定する。箱は入力方向へ動くが猫も追従し、箱に入る。後からもう一度動かして成功へ変更できない。
- 指を早く置いていても、動かさずに待ち、離陸後から横へ動かし始めた場合は有効。押下の早さではなく、横移動を始めた時刻で判断する。
- 指を離すまでに必要距離へ届かなかった場合は不成立。離陸後520msを過ぎてから必要距離へ届いても成功にはしない。
- 判定済みの遭遇で残りのアニメーションを飛ばしたり、次の遭遇を早めたりしない。早い入力の連打で遭遇数を増やせない。
- タイムアップ直前に成功条件を満たした入力は、その時点で成功確定済みとして計上してよい。着地アニメーションの遅延だけを理由に取り消さない。

### 8.7 中断

- 未成立のドラッグがキャンセルされたら、得点を変えずに中断する。再開時はその遭遇の`APPROACH`からやり直す。総残り時間は中断前の値を保持する。
- 成功確定済みなら、再開後に残る飛行・着地演出を完了させる。同じ成功や「スカッ！」を二重に発生させない。

| `HOLDING` | 押下時にパンチ時刻を3.2〜5.2秒の範囲で一度だけ決める | 予告開始で`WARNING`、指離しで`SUCCESS` |
| `WARNING` | パンチの650ms前から。前足を上げ、目線を変える | 指離しで`SUCCESS`、予定時刻到達で`PUNCH` |
| `SUCCESS` | 離した時の長押し秒数を確定 | 結果表示 |
| `PUNCH` | 記録なし。短い漫画的な反撃 | 結果表示 |

- 固定20秒などの全体セッションを設けない。1回押して離すだけの勝負。
- **得点になるのは指を離した時だけ**。長押し中の数値は未確定の現在値であり、最高記録へ保存しない。
- 猫が前足を上げる前に離しても成功として秒数を記録する。短く安全に止めることも、長く待って記録を狙うことも選べる。
- 200ms未満の押下は誤タップとして記録せず、失敗にもせずREADYへ戻る。
- パンチ時刻は押下時点で確定し、その後の指の動きや最高記録に応じて変更しない。警告650msは必ず同じ長さにする。
- `pointerup`の時刻がパンチ時刻未満なら成功。同時刻以上ならパンチが先に成立したものとして記録しない。
- パンチ成立後に指を離しても成功へ変更しない。押しっぱなしから次の試行を自動開始しない。
- 現在2.8秒／最高4.2秒という参考画像の状態は、この設定で自然に成立する。
- 最高記録は成功した試行の最大値だけ。前回より短い成功、失敗、キャンセルで最高値を消さない。
- 記録は端末内保存を基本とし、保存できない環境でもその場のプレイを妨げない。アカウント・オンラインランキングは不要。

### 9.6 キャンセル

- `pointercancel`、予期しないキャプチャ喪失、非表示化は、意図した`pointerup`ではない。表示中の2.8秒などを成功記録へ変換しない。
- その試行だけを取り消し、最高記録を保持したままREADYへ戻る。「失敗」と表示しない。
- `pointerleave`だけでは成功にしない。キャプチャした同じ指の`pointerup`を待つ。

1. 開始時の猫は帽子なし。
2. タップすると帽子をかぶせ、1回加点する。
3. 猫が自分で帽子を外す。
4. 帽子が完全に外れたら、またタップでかぶせられる。15秒繰り返す。

### 10.5 状態と初期値

| 状態 | 長さ | タップの扱い |
|---|---:|---|
| `BARE` | 次の有効タップまで | 1回だけ+1し、即`PUTTING_ON`へ |
| `PUTTING_ON` | 80ms | 加点しない |
| `WEARING` | 420〜920ms | 加点しない |
| `REMOVING` | 100ms | 加点しない。脱帽完了後に`BARE` |

- `BARE`で受け付けた最初のタップで、スコア更新と状態変更を同時に行う。アニメーションの終了時に再度加点しない。
- 帽子をかぶっている間や脱いでいる途中のタップは無効。入力を予約しておき、脱帽した瞬間に自動でかぶせ直すこともしない。

- 帽子の種類が変わる場合も、決まった順番の見た目変化にとどめる。レア度・所持数・装備画面などは設けない。
- 最初のタップも1回に数える。初回が早く、以降のサイクルと反応が速ければ、開始6秒ほどで8回・残り9秒という画像の状態を達成できる。
- 時間切れ時にかぶっている帽子はそのまま見せて結果表示へ進む。未確定のタップや途中の脱帽で点を足さない。

### 10.6 中断

- 確定済みの装着回数、帽子の有無、サイクルの残時間を保持する。再開で帽子を勝手に装着し直して加点しない。
- 未確定タップは破棄。再開ボタンを押したタップでは帽子をかぶせない。

背景 → 胸・前足 → 頭の基礎 → 頬メッシュ左右 → 鼻/口・目・眉（必要なものを固定または局所追従） → 髭 → 指 → 接触輪 → UI。

**もっとも品質リスクが高いモード。** 原本自体がすでに右頬を引っぱった状態であり、これをそのままさらに引っぱると歪みが累積する。正面の非変形の顔、左右の頬マスク、十分な外周余白、変形領域のテクスチャ、目・鼻の固定アンカーを追加制作する。

原則としてドラッグする側の頬だけを滑らかな減衰で変形し、反対の目・鼻・頭蓋の位置を保つ。瞳孔、鼻、歯、髭全部を同じ割合で伸ばさない。髭は根元を頬へ追従させ、先端は別制御または差分で処理。局所メッシュの三角形が反転しない上限を設定する。原本と同じつまみ位置・方向・伸び幅を再現できる照合用パラメータを持つ。

### 11.3 静止照合の要点

鼻が中央へ戻りすぎないこと、左右の目の高さと半眼、右端の頬の毛束、伸ばした白毛に不自然なぼけや縫い目がないこと。顔が一枚のゴムシートのように全体ごと変形する状態は不合格。離した後の自然な戻りは静止原本で検証できないため、追加の動作チェックが必須。

### 11.4 遊びの流れ

- 左右どちらかのほっぺを指でつまみ、そのままドラッグする。指を離すと、ぷるんと元へ戻る。
- 時間、点数、勝利、失敗、ライフは一切設けない。上達や達成を求めない自由遊びとする。

### 11.5 状態と初期値

| 状態 | 動作 |
|---|---|
| `IDLE` | 頬への押下待ち。自然なまばたき・呼吸 |
| `DRAGGING` | 押した側の頬だけを指に追従させる |
| `SPRING_BACK` | 指を離すと約450msで元へ戻す |

- 各頬のタッチ領域は、見た目の頬に沿った範囲を基準とし、最小48 CSS pxの操作幅を確保する。
- 触れた側の頬を操作対象として固定する。ドラッグが顔の中央をまたいでも、途中で反対側へ切り替えない。
- 変形量は指の移動に追従するが、最大水平変位を`0.16W`、最大垂直変位を`0.06H`に制限する。限界付近では移動が鈍くなるようにし、顔の輪郭が破綻しない。
- 顔の皮膚全体を雑に引き延ばさない。操作側の頬と口元だけを連動させ、目・瞳・鼻・耳・頭部の骨格を保つ。
- 元に戻る動きの初期値は約450ms、戻り過ぎは最大5%程度。痛そうな赤み・涙・傷は付けない。
- 戻っている途中でも、新しい押下があればその瞬間の頬の位置から操作を始められる。入力を待たせたり、突然基準位置へ戻したりしない。
- 頬以外から始まるドラッグでは変形しない。画面の戻るボタン等へ操作を誤転送しない。
- `pointercancel`では自然な形へ戻すだけ。非表示化から復帰しても頬を伸ばしたまま固着させない。

見下ろす角度、口と目、肉球の大きさ、上へ伸びる前足、羽の鮮やかな3色。視点を正面に変える、背景のラグを平板にする、棒を省くなどの簡略化をしない。タイマーの位置はR01/R02/R04とは異なる。

### 12.4 遊びの流れ

1. 猫じゃらしをドラッグして動かす。
2. 猫の前足が追いかけてくる。
3. 捕まらず15秒経てば成功。捕まると猫がじゃらしを抱えて得意顔になり、その試行が終わる。

### 12.5 位置・入力・初期値

- 猫じゃらしは、指で動かす`toyControlAnchor`と、肉球が実際に捕る`featherHitShape`を分ける。操作輪の中心と羽の先端・束は同一点とは限らない。
- `toyControlAnchor`の準備位置はR06原画像の右上の操作輪、概測`(0.90W, 0.18H)`を基準とし、重ね合わせで確定したアンカー座標を使用する。羽・棒の相対位置も原画像に合わせ、横中央へ一律変更しない。猫の準備ポーズは開始時に肉球と羽の判定形状が重ならないものにする。
- 操作点の移動可能領域`D_control`は、共通論理ステージ内でHUDと説明・ボタンを避けた領域として定義する。R06右上の操作輪を必ず含める。一定の内側余白によって、その位置を通常ドラッグで到達不能にしない。
- `D_control`の境界、`toyControlAnchor`、羽のローカル判定形状とオフセットを同じ参照データへ記録する。羽の形状はおもちゃの描画変換と同じ変換で更新する。
- 前足の到達可能域は、`D_control`の全位置に対応する**実際の羽の判定位置**を含むこと。操作輪と羽のオフセットを無視して両方へ同じ端制限を掛け、端の羽へ肉球が届かなくなる実装にしない。
- 操作輪を中心とする44 CSS px以上の有効領域への押下からドラッグする。押下した場所へ猫じゃらしを瞬間移動させず、押下時の`toyControlAnchor`に指の移動差分を加えて目標位置とする。
- おもちゃの最大移動速度は`2.5W/秒`。入力目標への追従として適用し、極端なポインター移動によるワープを防ぐ。
- 指を離すとその位置におもちゃが止まり、猫の追跡と15秒の時計は続く。再び操作輪の有効領域へ触れれば現在位置から操作できる。
- 新しい押下時には基準座標を取り直すだけ。離れた位置を交互にタップしてワープする攻略はできない。

### 12.6 猫の追跡と捕獲

- 前足の追跡目標は`featherHitShape`の現在位置であり、操作輪や指の位置ではない。
- 前足だけを際限なく伸ばして遠い位置へ届かせない。必要に応じて猫の体の位置・向きも追従させる専用の俯瞰移動・手伸ばしポーズを制作し、骨格と接触位置を保つ。すべての羽の位置へ到達することを保ち、描画をその移動へ追従させる。プレイヤーの操作は1本指のドラッグだけで変わらない。
- 初期追跡速度は`0.55W/秒`、15秒時点では`0.85W/秒`。この間を一定の割合で変化させる。途中で予告なく瞬間移動したり、入力に応じて速度を急上昇させたりしない。
- 捕獲は肉球の`pawHitShape`と羽の`featherHitShape`の重なりで判定する。初期の円近似では、それぞれの判定中心の距離`0.10W`以下を出発点とし、羽と肉球の見た目に合わせて楕円・輪郭・半径を調整する。`0.10W`を操作輪との距離へ適用しない。
- 操作輪、棒、操作軌跡、指の位置、HUDとの接触では捕獲しない。通常ドラッグで原本の操作点と羽の配置を再現しながら、見た目の肉球と羽の接触だけが勝敗へつながること。
- 高速のドラッグで1フレーム中に前足を通り抜けないよう、前フレームから現在までの相対移動区間についても接触を判定する。
- 捕獲するとその時点の有効経過秒数を記録して終了する。15秒経過時点まで接触しなければ15.0秒として成功。
- 同一更新内で捕獲と15秒到達が両方起こる場合は発生時刻を比較し、15秒より前の接触だけを失敗にする。描画フレームの順番だけで勝敗を変えない。

### 12.7 画面の隅へ置きっぱなしにできない理由

- `D_control`の四隅・境界に操作輪を置いたときの羽の位置を計算し、そのすべてへ肉球が到達できるようにする。操作輪ではなく羽との当たり判定を使っても、端に安全地帯が生まれないことを確認する。
- じゃらしを置きっぱなしにすると、猫は止まらずその位置へ近づき、捕獲する。HUDの裏・画面の外・指の再押下位置などに安全地帯を作らない。
- 静止した羽へ到達する距離と最低追跡速度から、すべての境界位置で15秒より十分短く捕獲できることを確認する。体の移動アニメーションや端の制限を理由に、論理的な追跡だけが止まらないようにする。
- 画面隅を特別な即死エリアにしたり、新しい操作・複雑な警告ゲージを追加したりする必要はない。

### 12.8 中断

- 通常の`pointerup`はおもちゃを止めるだけで、中断ではない。
- `pointercancel`やアプリの非表示化は中断。残り時間・前足位置・おもちゃ位置を保持し、再開操作を待つ。
- 再開時は指の基準点を新しく設定し、おもちゃ位置は保持する。再開ボタンの座標へ飛ばさない。
- 「再開」を押した直後は操作準備状態とし、次の操作輪の有効領域への`pointerdown`で追跡と時計を再開する。その押下が新しいドラッグの始点になる。指を操作位置へ戻している間に捕まることを防ぐ。
- 初回開始も、操作輪の有効領域への最初の押下で追跡と時計を動かし、そのままドラッグする。別の開始用タップや2回目の押下を要求しない。

## 13 共通の入力・時間・音・保存

### 13.1 開始と時間

- ①②④⑥は `READY → PLAYING → RESULT`。最初の操作は次の表どおりとし、開始処理と通常入力処理の両方から同じ入力を採点しない。

| モード | READYからの開始操作 | その操作の採点 |
|---|---|---|
| ① | 猫への最初の有効タップを離した時 | 時計開始と同時に1回だけ+1。開始時は閉眼 |
| ② | 最初の有効タップを離した時 | 時計と接近を開始するだけ。次の新しい押下からスワイプを受け付ける |
| ③ | 操作領域への長押しの押下時 | 現在秒数の計測開始。成功して離すまで記録しない |
| ④ | 帽子なしの猫への最初の有効タップを離した時 | 時計開始と同時に帽子を装着して1回だけ+1 |
| ⑤ | 画面表示後すぐ操作可能 | 採点なし |
| ⑥ | 猫じゃらしの操作輪への押下時 | 時計・追跡を開始し、その押下からドラッグできる |

- メニューでカードを押した指は、上記の最初の操作に流用しない。一度離してから新しい操作を受け付ける。
- READY中はタイマーも猫の攻撃判定も進めない。プレイ画面の必要な画像・アニメーションが読み込まれてから開始できるようにする。
- ③は最初の長押しで試行開始。⑤は表示直後から自由に操作できる。
- 経過時間は `performance.now()` に基づく単調増加時計から中断時間を除いて求める。フレーム数や `setInterval` の呼び出し回数で残り時間を数えない。
- ①②④⑥の表示残秒は `ceil(max(0, 制限秒数 - 有効経過秒数))`。たとえば④は開始時15秒、6秒経過時9秒となる。⑥もプレイ中の「あと6秒」等は整数で表示する。
- 終了時刻以上の入力は加点しない。各入力を処理する前に、その入力の時刻までゲーム状態を進めてから判定する。
- ③の現在・最高秒数と⑥の結果の生存秒数は小数1桁で表示する。確定記録は `floor(秒数 × 10) / 10` とし、表示より長く生存した／押したと扱わない。
- RESULTは時間経過で勝手に閉じない。「もう一度」「メニュー」を押して次へ進む。
- メニューへ戻る操作は即座に現在のプレイを中断する。未確定の途中記録を完成記録として保存しない。

### 13.2 Pointer Eventsの共通契約

- `pointerdown / pointermove / pointerup / pointercancel / lostpointercapture` を使用する。タッチ用とマウス用の別実装を作らない。
- ゲーム領域だけに `touch-action: none` を指定する。メニュー・戻る・再開などの通常ボタンをゲーム操作のヒット領域に含めない。
- アクティブな `pointerId` は常に1つ。操作中に来た2本目以降の指は無視し、操作中の指が離れても別の指へ自動で引き継がない。
- 有効な `pointerdown` で `setPointerCapture(pointerId)`。画面外へ少し指が動いても、単なる `pointerleave` を成功・失敗・指離しとして扱わない。
- タップは「押下から300ms以内に離す」「押下地点からの最大移動12 CSS px以下」を両方満たしたもの。押しっぱなしの自動リピートは発生させない。
- ①④の加点候補は押下時の状態を記録し、有効な `pointerup` 時に1回だけ確定する。①は開眼後120msまでの猶予中に離せば、閉眼中の有効な押下を突然ミスにしない。猶予終了後も指が残った場合は、後述の継続接触判定を優先する。制限時間後まで離さなかったタップは無効。
- ①④の加点候補を受け付ける間隔は150ms以上。①の発見判定はこの間隔制限と別で、開眼中の接触を取りこぼさない。同じ操作の `click` イベントを追加で採点しない。ゲーム動作はPointer Events側で一度だけ処理する。
- `pointerup` を正常処理したら、アクティブな入力をクリアしてからキャプチャを解放する。続けて発生する `lostpointercapture` で正常終了をキャンセルしない。
- 距離は941×1672の共通論理ステージへ変換して判定する。本書の `W = 941`、`H = 1672` であり、HUDを除いた矩形の幅・高さではない。12 CSS px等の入力上の距離だけはCSS座標で評価する。操作可能域は、この共通座標系の中に、HUD・ボタンを除く領域として別途定義する。
- OSのジェスチャー、着信、アプリ切替などによるキャンセルを、成功タップや意図した指離しに変換しない。

### 13.3 中断と復帰

- 非表示化・ウィンドウフォーカス喪失・有効な操作中の予期しないキャプチャ喪失では、ゲーム時間・猫の進行・衝突判定を停止する。バックグラウンドの時間で負けたり、勝手に記録が伸びたりしない。
- ①②④⑥は「再開」操作を待つ。復帰しただけで自動再開しない。再開ボタンを押した入力をプレイ入力に流用しない。
- ③の長押し中断は**試行の取り消し**。秒数を確定せず、失敗にも数えず、最高記録を保持してREADYへ戻す。
- ⑤の中断では頬を自然な形へ戻す。失敗扱いは存在しない。
- ①④の未確定タップは破棄する。既に確定した回数は保持する。
- ②は未成立のスワイプ中なら、その1回の遭遇を得点なし・失敗なしでやり直す。既に成功・早すぎ・遅すぎの判定が確定していた場合は、その判定を保持する。
- ⑥は猫とおもちゃの位置、有効経過時間を保持し、再開後はそこから続く。キャンセルを利用した位置の瞬間移動はできない。
- スコアが増えるのは明示した成功イベントのみ。中断・再開・アニメーション終了・状態への再入場自体では加点しない。

Pointer Events、pointer capture、touch-action等の機能は[S4]、非表示時の描画・タイマー抑制は[S5]を参照。音・アニメーションも時計とともに止め、復帰時の大きなdeltaをそのまま進めない。表示アイコンが小さくてもUIボタンのタッチ領域は44×44CSSpx以上を初期基準とし、ゲーム操作領域と重ねない。

### 13.4 音とアクセシビリティ

最初の明示的な操作を契機に音声を初期化する。自動再生が拒否された場合もゲームは無音で進める。メニューの音ボタンは常に使え、設定を端末内へ保存する。[S6]

警告は音だけにせず、目、前足、マーク、表情でも分かるようにする。色だけで成功・失敗を区別しない。動きを減らす設定では画面揺れや大きい星の演出を減らし、ゲームの予告は残す。メニュー・結果・設定はキーボードで操作できる。時間勝負の操作まで完全な支援技術対応を保証する記述はしないが、ルールと記録はDOMで読み取れるようにする。

### 13.5 保存データ

保存キーは `nekotsubushi:v1`。内容は、schemaVersion、音設定、動き軽減設定、各モードの最高記録、説明既読フラグとする。氏名・メール・位置情報等は不要。

数値は整数の回数またはミリ秒で保存し、表示時に秒へ変換する。05にダミーのスコアを保存しない。06はベスト生存時間とクリア回数を別項目にする。localStorageが使えない場合はメモリだけで遊べるようにし、毎回の操作をエラーにしない。データが壊れていれば既定値へ戻す。

## 15 画像を逐一見て再現する制作手順

### 15.1 1つの部位を仕上げるループ

1. 対象モードの原本を開き、全体と対象部位の拡大を確認する。
2. 構図、位置、サイズ、色、毛・輪郭、前後関係を記録する。
3. 対象素材を制作または配置し、その部位を実装する。
4. 実際のゲームを原本と同じ状態に固定して、画面をキャプチャする。
5. 原本と実装を横に並べ、50%の透過重ね合わせと差分画像を見る。
6. 大きな違いを直し、再キャプチャする。画像を見ず記憶だけで調整しない。
7. 静止状態が揃ったら動かし、継ぎ目・影・操作との一致を確認する。

作業順は、背景とカメラ → 猫の大きさと輪郭 → 顔 → 被毛と髭 → 小物と影 → UI → 演出、とする。毛の細部より先に、猫が大きすぎる・鼻の位置が違うといった構図のずれを直す。

### 15.2 照合用状態

開発環境に `mode`、`fixture`、`seed`、`time` を指定できる検証入口を設ける。一般のメニューへ開発用UIは出さない。例えば `mode=05&fixture=reference` は、通常の頬変形処理を使ってR05の状態に固定する。

`visual_fixtures.json` は状態の意図を記録する契約ファイルであり、ゲームコードではない。実装時にScene側へ結び付ける。照合時にはフォントと全素材の読込を待ち、乱数とゲーム時計を固定し、アイドル動作を停止する。

### 15.3 キャプチャの条件

| 検査 | 条件 |
| --- | --- |
| 正本との比較 | ゲームステージ部分を941×1672pxで取得。外側の共通ナビを除く |
| スマホ表示 | 390×844、360×800、375×667などのCSSビューポートで破綻確認 |
| PC | 1440×900程度で中央の縦ステージとマウス操作を確認 |
| 同一環境の回帰 | ブラウザ・OS・DPR・フォント・乱数を固定した承認済み基準画像と比較 |
| 動き | 通常→入力→成功/失敗→復帰を動画または連続フレームで確認 |

Playwright等の画面比較は、原本との目視照合を終えた後の回帰検査にも使う。同じアプリでもOS・ブラウザ・描画環境で画素が変わり得るため、回帰比較の環境を固定する。[S9]

### 15.4 合否の基準

原本との比較では、近似座標表の±0.02を許容値として使わない。初期の目安として、鼻・目・小物接点等のアンカーは原本幅/高さの約0.5%以内、主要UIの外枠と猫の大きさは約1%以内を目指す。最終値は原本と重ねて確定する。これは作業開始時の目標であり、計測済み精度ではない。

自動差分のしきい値だけで見た目の合格にしない。特に猫の顔・毛・髭・頬の接写は人の目で確認する。回帰比較のしきい値を変更して差分を消す場合は理由を記録し、原本や承認画像を無断で差し替えない。

| 優先度 | 問題例 | 扱い |
| --- | --- | --- |
| P0 | 起動不能、操作不能、別モード、データ破損 | 解消まで納品不可 |
| P1 | 別の猫、低品質な毛、原本の構図違い、頬/腕が破綻、見た目と判定が不一致 | 解消まで納品不可 |
| P2 | 文字切れ、色/位置の明確なずれ、指や帽子の残像、スマホで押せない | 解消まで納品不可 |
| P3 | 小さい粒子や影の軽微な差など | 明示して次の改善候補にできる |

`qa/report.md` に、参照原本、ブラウザ条件、対象状態、観測差分、修正内容、キャプチャの場所、残る問題、合否を残す。「見た目はだいたい同じ」の一文だけでは完了報告にしない。

判定の境界、キャンセル、中断復帰、モードの破棄は小さい自動テストで確認する。ゲームの見た目だけをまねるテストや、実装と同じ式を写しただけのテストは増やさない。

### 16.2 初期の性能予算

以下は保証済みの実測値ではなく、制作開始用の目標。採用する実機を記録して測る。

| 項目 | 初期目標 |
| --- | --- |
| 初回メニューの通信 | コード・フォント・サムネイルの合計約1.2MiB以内 |
| 選択モードの追加通信 | 約4MiBを目標。品質維持に必要な超過は計測して判断 |
| メニュー操作可能 | 10Mbps・RTT100ms相当で3秒以内を目標 |
| モードの準備 | 同条件で5秒以内を目標。待機表示と再試行を持つ |
| 描画 | 60fps目標。最低対象実機で継続30fps以上を初期ゲート候補 |
| 入力の反応 | タッチから最初の見える反応まで100ms以内を目標 |
| 画像テクスチャの常駐 | 64〜128MiBを初期予算。その他のバッファは別途集計 |
| 読込・解放 | 共通＋使用中の1モードを中心に保持し、不要な前モードを解放 |

941×1672のRGBA8画像は、画素だけで6,293,408バイト、約6.00MiB。これを24枚同時に展開すると約144MiBになる。2048×2048のRGBA8アトラスは16MiB。PNG/WebPの通信サイズとは別に、展開後のメモリを集計する。ミップマップや描画バッファも加わる。

画面全体の連番ではなく、背景と猫を分け、動く部位と必要なフレームだけを持つ。性能調整では背景解像度、粒子、常駐数、不要なマスクから見直し、猫の顔・毛並みを先に粗くしない。スプライトシートや不要テクスチャの管理は公式の性能資料も確認する。[S3]

対象ブラウザは実装着手時点のiOS Safari、Android Chrome、PC Chrome/Edge/Safariの主要現行版をまず確認し、実際に試したOS・端末・ブラウザ版を納品記録に書く。エミュレーションだけで実機合格とはしない。WebGLコンテキスト喪失時は停止→再読込または再試行の導線を用意する。

| F 統合 | 6モードの切替、端末内記録、音、実機性能 | 受入チェックに合格 |
| G 公開準備 | 配信設定、素材の権利/出所、公開URLの動作確認 | 公開先に応じた確認が完了 |

「全部を仮の猫で作ってから絵を置き換える」工程に偏らず、早期に高品質素材で01・05の実現性を確認する。これはユーザーへの新しい承認待ちを増やすためでなく、後戻りを早く見つけるための内部ゲートである。

### 17.2 実装担当が最終的に納めるもの

- 6モードが実際に動くWebアプリのソースと起動手順。
- 本番用アセット、編集用マスター、採用素材のメタデータと出所一覧。
- 原画像と承認済み比較キャプチャ、透過重ね合わせ、差分、動作確認記録。
- テストした端末・ブラウザと性能計測、既知の問題。
- アプリの公開が依頼された場合は、公開先で確認したURLと配信設定。

### 17.3 完成の宣言条件

6モードが選べること、実際に操作できること、照合状態が原画像と揃うこと、猫が動いたときにも品質を保つこと、戻る・再試行・中断が壊れないことを確認してから完成とする。未制作の素材や未確認の端末は明示する。ビルド成功や静止画像の一致だけをもって完成とはしない。
