# 継続・再挑戦・友人比較の改善仕様

ルール版は **2**。既存の6モードと指1本の操作を保ち、結果から次の目標を読み取り、すぐ再挑戦できるようにする。ログイン・サーバー保存・全体ランキングは追加しない。

## ゲームと順位

| モード | 追加判定 | 比較する順序 |
| --- | --- | --- |
| 01 ねこつんつん | 有効タップの連続数。見つかると連続を解除。予告の最後200msまたは既存の開眼猶予中の成功を「ギリギリ」にする。 | 成功回数 → 最大連続数 → ギリギリ回数。各値は大きいほど上位。 |
| 02 箱をずらせ | 箱が成功位置に達した時刻で分類。離陸後300ms未満は早め、300ms以上440ms未満はぴったり、440ms以上520ms以内はギリギリ。早すぎる移動・失敗で連続を解除。 | 成功回数 → 最大連続数 → ぴったり回数。 |
| 03 猫パンチ寸止め | 成功した解放時の残り時間を整数msで記録。パンチの時刻は同じ試行中の短いタップや取消で再抽選しない。 | 成功を優先し、残りmsが小さいほど上位。失敗同士は同点。 |
| 04 その帽子、いやニャ！ | 帽子が外れてから180ms以内の有効な装着をぴったりとする。初回は評価対象外。遅い装着・帽子着用中の無効タップでぴったり連続を解除。先行入力は予約しない。 | 装着回数 → ぴったり回数 → 最大ぴったり連続数。 |
| 05 ほっぺむにむに | 6種類の触り方で表情を発見。時間・得点・失敗は設けない。 | 競争対象にしない。 |
| 06 あとちょっとで届くのに | 生存時間をmsで記録。羽と手の距離が接触半径より外側で、ステージ幅の22％以内にあった区間をひやひや時間に加算。接触後・中断中は除外。 | 生存時間 → ひやひや時間。各値は長いほど上位。 |

比較する全項目が等しければ同点。モードやルール版が違う成績は比較しない。結果は今回・前回・自己ベストと必要な副指標を示す。寸止めは成功時の残り時間を表示し、計測していない「何ms遅れたか」は表示しない。

「もう1回！」は同じSceneとデコード済み素材を再利用し、時計・入力・帽子・演出をリセットする。通常モードは新しいseed、日替わり・友人挑戦は元のseedを使用する。箱の中断で未解決の出題を別の乱数へ差し替えない。

## 日替わりと挑戦状

日本時間（UTC+9）の午前0時で日付を区切る。2026年1月1日を起点として01・02・03・04・06を循環する。seedは `2|daily|YYYY-MM-DD|mode` のFNV-1a 32bit値。日付とルール版が同じなら条件は固定される。

日付をまたいでも開始したお題を継続でき、再挑戦も同じお題。メニューは現在の日本時間のお題に更新する。過去の日付のリンクもその日付で再現する。

- 日替わりURL：`/?daily=YYYY-MM-DD&mode=N`。日付とモードが一致することを検証する。
- 挑戦URL：`/?challenge=TOKEN`。TOKENはASCII JSONのbase64url、末尾の`=`は除く。
- JSON形式：`{v:2,m:mode,s:uint32Seed,d?:dailyDate,r:[success,count,maxStreak,specialCount,perfectCount,maxPerfectStreak,remainingMs,survivalMs,nearMissMs]}`。`success`は0または1。
- 日替わり由来の挑戦は日付・モード・seedの一致を検証する。モード05、負値、非整数、過大値、不正日付、重複TOKEN、未対応ルール版を受け付けない。
- URLは2048文字以内、TOKENは1800文字以内。テスト・fixture・captureなどの開発用パラメーターは共有URLへ持ち込まない。

受け取った人は同じseedのゲームで目標と比較し、自分の結果を載せた返信リンクを送れる。記録は端末からの自己申告であり、サーバー検証済みの公式記録ではない。

共有画像は同一配信元の猫素材とローカルフォントを使った1080×1350 PNG。OS共有が利用可能ならユーザー操作から呼び出し、非対応時はリンクコピー・画像保存を提供する。OS共有の取消で結果や再挑戦を失わない。

## 12種類の表情と仕草

| 表情 | 発見条件 |
| --- | --- |
| 右にむに〜／左にむに〜 | 対応する頬を外へ引いて離す。 |
| きゅっと上向き／ぷくっと下向き | 頬を上／下へ引いて離す。 |
| もちもち | 頬を鼻の方向へ寄せて離す。 |
| うっとり | 頬を小さく引いた状態で1秒保って離す。 |
| しらんぷり | ねこつんつん10連続。 |
| あれ、箱は？ | 箱をずらせ3連続成功。 |
| すんっ | 猫パンチ寸止めの成功時、残り100ms以内。 |
| ぷいっ | 帽子のぴったり3連続。 |
| むむっ | 羽を15秒守り切る。 |
| びっくり！ | 既に保存した自己ベストを更新する。初回記録では解放しない。 |

頬は実際の制限付き変位で判定する。横60px、縦40pxを目安に主方向を選び、長押しは変位20px以上60px未満と1秒以上の保持で判定する。1操作につき1種類、取消操作では解放しない。座標は941×1672の論理ステージ上の値。

発見は一度だけ保存する。コレクションには未発見時もヒントを表示し、発見後は参照画像から制作した表情カードと「仕草をみる」を表示する。仕草は実際のScene上の目・耳などの局所的な動きで再生し、カード画像をゲーム全面へ貼り付ける方式は使用しない。動きをひかえる設定にも対応する。

## 保存と互換性

保存キーは `nekotsubushi:v2`。旧 `nekotsubushi:v1` を削除・上書きせず、設定・既存の回数・生存時間・閲覧済みモード・クリア数を引き継ぐ。

寸止めの旧「長押し時間」は、新しい残り時間に換算できないため `legacyRecords['3']` に残し、UIでも旧記録として区別する。新しい寸止めの失敗は直前の試行として保存するが、自己ベストにはしない。

通常モードの自己ベストはモード単位。日替わりと友人挑戦はルール版・モード・seed・日付のコース単位で保存し、同じお題なら両者でベストを共有する。お題別履歴は直近90コース、各コースにベストと直前記録を持つ。通常ベストと発見済み表情はこの90件制限に含めない。

保存形式や値を検証し、破損したv2は残っているv1から復帰を試みる。保存不能でもメモリ上でプレイを継続する。fixture・テスト時計などを使ったプレビューの記録・表情解放は保存せず、挑戦状も生成しない。

## 検証コマンドと対象

```sh
npm test
npm run build
npm run test:replay
BROWSER=webkit npm run test:replay
BASE_URL=https://nekotsubushi.vercel.app npm run test:replay
```

単体テストは69件の成功を確認済み。新機能ブラウザ検査は6モード、日替わり、別ブラウザでの挑戦比較、共有の代替操作と取消、保存移行、表情発見と実Scene再生、20回再挑戦、スマホ／PC相当の画面、保存不能を対象とする。実行結果・計測・画面は `artifacts/replay/{chromium,webkit}/report.json` と同ディレクトリを参照する。成否と対象版は各実行のレポートを参照する。

GitHub ActionsでNode.js 24、Chromium／WebKitの行列を設定する。検査用の各ブラウザは `npx playwright install --with-deps chromium webkit` で用意できる。`BASE_URL` 省略時はlocalhostのViteを自動起動し、公開URLへの検査ではサーバーを起動しない。

Linux WebKitとスマホ相当のビューポートは物理iPhone Safariの実機検査ではない。実機OSの共有画面、発熱、長時間性能はこの自動検査だけでは確認できない。
